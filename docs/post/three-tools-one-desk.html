《人到中年》｜三套工具，一张桌子

三套工具，一张桌子

我一度以为，所谓「用上 AI」，就是多开几个窗口。

左边是本机的 Codex，适合改文件、跑命令、把一件事做完。右边是一排会定时起床的机器人：有的看社交平台互动，有的等我点头再发文章，有的帮我筛线上短单。再往外，还有网页版大模型，随时能聊两句。

工具越多，我越容易做一件蠢事：把聊天记录当成档案。

对话很舒服。它记得上下文，会顺着你的语气往下接。可它也有三个毛病。第一，对话散在各自的产品里，Copilot、网页、本机助手并不共享同一本账。第二，真正要执行的事——发帖、改库、跟进一单——往往发生在别处，聊天里只剩摘要。第三，敏感内容稍一复制，就可能进到不该进的历史里。

于是我给自己定了一条很笨、但管用的规矩：

AI 可以很多，桌子只准一张。那张桌子是 Obsidian。

一张桌子，三种角色

我把日常协作拆成三个角色，故意不让它们抢同一件事。

Codex（本机）负责「动手」。它在我的电脑上读写项目、检查配置、把任务做完。它强的是工具链和目录权限，不是再开一个网页聊天窗。

Grok Bot（一排专职助手）负责「站岗」。有的按点巡检，有的等我下令才发布，有的只在我确认报价后才外发。它们之间由一个「管家」协调，而不是彼此私聊当真相。

Obsidian负责「唯一存档」。日程、项目、OKR、机器人日汇总，以及 Codex 交出来的结论，都落到同一个库。聊天可以提醒我，但提醒不是档案。

这样分工之后，问题就清楚了：Codex 和机器人如何协作？我试过两条岔路，最后都退回第三种。

一条是再开一个「网页版大模型 bot」，让机器人去点网页。偶发问问可以，当同事不行——页面一改就碎，也拿不到本机文件权限。

另一条是在云电脑再装一套 Codex，指望和本机「同步」。账号可以两边登录，会话、本地记忆、工作区并不会自动变成同一本。云上的 Codex 是第二张工位，不是镜子。

所以我选了最土的桥：只通过 Obsidian 交接。

桥长什么样

桥分两截，都很短。

1. Codex 写出来

本机有一份 skill，名字叫 obsidian-bot-bridge。它的要求很具体：

  • 凡是任务产生了可延续的结论、状态、阻塞或交付物，结束前必须在库里写一份交接笔记；
  • 纯闲聊可以跳过，但要在回复里标明跳过；
  • 交接放在固定目录，并更新一份「未读索引」，方便管家扫描；
  • 禁止把密码、密钥、精确财务与健康原始材料、不宜公开的身份细节写进笔记。

这和我给 Codex 定的另一条原则并不打架：本机磁盘能不写就不写。交接笔记是我规定的必要交付，不是给模型图方便的平行副本。一份就够，不要在桌面再落一份。

2. 机器人读进去

管家机器人每天会整理各 bot 的进展，写入当日日记里的「Bot 日汇总」。现在它多扫一眼 Codex 的未读索引和当日交接文件：有结论就摘要进日记，有需要分派的就点名对应的专职 bot。

其他 bot 默认不抢读。交接里写明受众时，才轮到它们行动。

于是形成闭环：

人决策 → Codex 做事并写交接 → 管家读库汇总 → 专职 bot 执行站岗任务 → 结果再回库。

没有谁把聊天记录当成第二套真相。

库里怎样摆，才不散架

若只有「往笔记里扔文件」，桌子还是会脏。我把个人管理系统分成几层，写进库根的约定里：

  • 资料层：原始材料只增不改；整理后的知识进 wiki。
  • 管理层：OKR、项目、复盘、日程。
  • 机器人层：注册表、日汇总规则、以及 Codex 交接目录。

项目必须有完成条件和下一步；日记用来选当天最重要的几件事，而不是自动把昨天的未完成复制过来。敏感原则写在明处：管理层默认私密；健康与财富只留决策需要的聚合结果。

机器人再多，也只是管理层的执行触手。新建专职 bot 要先评估、我同意再建——避免「每个念头一个助手」。

脱敏不是客气话

多人、多助手写同一个库时，最大的风险不是格式不统一，而是随手粘贴。

我要求所有写入方遵守同一条硬规则：密钥、Token、私钥、可登录的账号口令组合、精确账户与体检原件、旧雇主与不宜公开的身份细节，一律不进笔记。公开写作（网站、社交平台）另有品牌边界：不写旧身份，不把私密库里的家庭与财务细节抖出去。

库本身还有一套加密备份：源库不做 git init，由本机任务把合规文件加密后推到私有远程；公开库只接受我手工点名的白名单。备份解决的是「第二份在哪」；脱敏解决的是「第二份里该不该有这些字」。两件事都要，缺一不可。

我实际得到了什么

说收益之前，先说代价。

代价是：多写几步。Codex 结束时要落交接；我要看日记和项目页，而不是只刷聊天。机器人不会替我做 WIP 选择——同时开太多 P1 项目，系统帮不了忙。

换来的是三种清晰：

  1. 真相只有一份。 问「短单跟到哪了」「今天 bot 做了什么」，先打开库，而不是翻三个产品的历史。
  2. 职责不再打架。 本机动手的、云侧站岗的、网页偶发问一句的，各走各的门。
  3. 公开与私密分开。 对内交接可以谈阻塞；对外发布仍走审批和品牌口径。

这不是「全自动人生」。它更像把书桌收拾到一个程度：东西仍会来，但知道该放哪一层。

若你也想搭类似的桥

不必复制我的工具名单。值得抄的是结构：

  1. 指定唯一档案（可以是 Obsidian，也可以是别的本地库），聊天降级为提醒。
  2. 分清动手的和站岗的，不要让网页聊天冒充文件权限。
  3. 给动手的一方一条强制 skill/清单：任务结束写短交接、更新未读、脱敏。
  4. 给站岗的一方一个固定读取点：索引 + 当日文件，而不是「记得昨天聊过」。
  5. 备份与脱敏分开做；私钥与公开白名单尤其要当回事。

我仍在用这套结构：日记有时会空，项目有时会贪多，交接有时会忘——那是人的问题，不是再买一个助手能自动消失的问题。桌子在，至少知道扫哪里。

题外一句

有人问：这篇该让哪个模型写？

事实层适合由把桥搭起来的人（或那个管家）写清楚；语气可以再请别的模型润色。让一个没经手过的网页模型从零编造你的系统，通常会漂亮，但不准。

准，比漂亮先重要一步。
